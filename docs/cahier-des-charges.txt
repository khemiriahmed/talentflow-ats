1. Présentation du projet
1.1 Contexte
Les services RH gèrent souvent les offres, les candidatures et les entretiens avec des
outils dispersés (emails, tableurs, messageries). Ce projet vise à centraliser tout le
processus de recrutement dans une application web unique : un ATS (Applicant Tracking
System).
1.2 Objectifs
Centraliser la publication des offres et la réception des candidatures.
Suivre chaque candidat dans un pipeline visuel (kanban).
Planifier les entretiens et collecter les feedbacks des managers.
Notifier automatiquement les parties prenantes.
Fournir des indicateurs de pilotage au service RH.
Démontrer une architecture professionnelle (conteneurisée, déployable sur le cloud,
testée, documentée) dans un contexte portfolio.
1.3 Périmètre
Inclus : gestion des utilisateurs et rôles, offres d'emploi, candidatures, upload et
consultation de CV, pipeline kanban, entretiens, notifications email, dashboard,
déploiement cloud.
Hors périmètre (v1) : parsing automatique de CV par IA, paiement, application mobile
native, signature électronique, multi-entreprises (multi-tenant).

3. Besoins fonctionnels
3.1 Authentification et comptes
RF-01 : inscription candidat par email + mot de passe, avec vérification d'email.
RF-02 : connexion avec JWT (access token + refresh token).
RF-03 : réinitialisation du mot de passe par email.
RF-04 : gestion du profil (nom, téléphone, photo, LinkedIn).
RF-05 : l'Admin peut créer des comptes RH/Manager, activer/désactiver un compte et
changer un rôle.
3.2 Offres d'emploi
RF-10 : créer, modifier, supprimer une offre (titre, description, département, lieu, type
de contrat, fourchette de salaire optionnelle, compétences requises, date limite).
RF-11 : statuts d'une offre : Brouillon, Publiée, Clôturée, Archivée.
RF-12 : liste publique des offres avec pagination, recherche par mot-clé et filtres (lieu,
contrat, département).
RF-13 : assigner un manager responsable à une offre.
3.3 Candidatures
RF-20 : le candidat postule à une offre avec CV (PDF, 5 Mo max) et lettre de motivation
optionnelle.
RF-21 : un candidat ne peut postuler qu'une fois par offre.
RF-22 : le candidat suit le statut de ses candidatures.
RF-23 : le candidat peut retirer sa candidature.
RF-24 : la RH consulte, télécharge le CV, ajoute des notes internes et des tags.
RF-25 : recherche et filtres sur les candidatures (offre, statut, date, tag).
Rôle Description Droits principaux
RH Recruteur CRUD offres, voir tous les candidats, gérer le
pipeline, planifier des entretiens, dashboard
Manager Responsable d'équipe Voir les candidatures de ses offres, donner un
feedback, participer aux entretiens
Admin Administrateur technique Gérer les utilisateurs et les rôles, paramètres
généraux, audit

3.4 Pipeline de recrutement (kanban)
RF-30 : étapes par défaut : Reçue → Présélection → Entretien RH → Entretien
technique → Offre → Embauché / Refusé.
RF-31 : déplacer une candidature d'une étape à l'autre par drag & drop.
RF-32 : chaque changement d'étape est historisé (qui, quand, ancienne et nouvelle
étape).
RF-33 : un motif est obligatoire en cas de refus.
3.5 Entretiens
RF-40 : planifier un entretien (date, heure, durée, type visio/présentiel, lien ou lieu,
participants).
RF-41 : le candidat et les participants reçoivent une invitation par email.
RF-42 : le manager saisit un feedback (note de 1 à 5, points forts, points faibles,
recommandation).
RF-43 : vue calendrier des entretiens pour la RH et les managers.
3.6 Notifications
RF-50 : emails automatiques : confirmation de candidature, changement de statut,
invitation à un entretien, rappel 24 h avant.
RF-51 : notifications in-app (cloche) pour la RH et les managers.
RF-52 : modèles d'emails paramétrables.
3.7 Dashboard et reporting
RF-60 : nombre de candidatures par offre et par période.
RF-61 : taux de conversion par étape du pipeline.
RF-62 : temps moyen de recrutement (time-to-hire).
RF-63 : répartition par source de candidature.
RF-64 : export CSV des candidatures.
3.8 Administration et audit
RF-70 : journal d'audit des actions sensibles (création/suppression, changement de
rôle, refus, export).
RF-71 : gestion des utilisateurs (liste, recherche, activation).

5.2 Architecture
Application monolithique modulaire en v1 (un module par domaine métier : auth, job,
application, interview, notification, storage), avec possibilité d'extraire le module
notification en microservice par la suite.
API REST versionnée ( /api/v1/... ), échanges JSON.
Pattern StorageService  (interface) avec implémentations MinIO/S3 et GCS,
sélectionnées par profil Spring.
Frontend SPA communiquant avec l'API via un interceptor JWT.
5.3 Infrastructure et DevOps
Docker : Dockerfile multi-stage pour le backend (build Maven puis JRE léger) et le
frontend (build Node puis Nginx).
Docker Compose : services postgres , redis , minio , mailhog , backend ,
frontend , pgadmin  (profil dev).
CI/CD : GitHub Actions (build, tests, analyse qualité, build des images, push vers ECR
ou Artifact Registry, déploiement).
Cloud :
Option AWS : ECS (Fargate) ou EC2, RDS PostgreSQL, S3, SES, Secrets Manager,
CloudWatch.
Option GCP : Cloud Run, Cloud SQL, Cloud Storage, Secret Manager, Cloud
Logging.
Couche Technologie
Frontend Angular (standalone components, lazy loading),
Angular Material ou PrimeNG, Angular CDK (drag &
drop)
Base de données PostgreSQL 16
Cache Redis
Stockage fichiers MinIO en local, AWS S3 ou Google Cloud Storage en
production
Emails MailHog en local, AWS SES ou SMTP en production
Documentation API SpringDoc OpenAPI (Swagger UI)
Tests JUnit 5, Mockito, Testcontainers, Jasmine/Karma
ou Jest, Cypress ou Playwright (E2E)

8. Écrans principaux (frontend)
Public : accueil, liste des offres, détail d'une offre, connexion/inscription.
Candidat : mes candidatures, profil.
RH : gestion des offres, liste des candidatures, fiche candidat, pipeline kanban,
calendrier des entretiens, dashboard.
Manager : mes offres, candidatures à évaluer, feedbacks.
Admin : utilisateurs, audit, paramètres.
9. Sécurité et conformité
Autorisation par rôle côté backend ( @PreAuthorize ) et côté frontend (guards).
Un candidat ne peut accéder qu'à ses propres données.
Validation du type et de la taille des fichiers uploadés (PDF uniquement), analyse du
nom, stockage hors du système de fichiers applicatif.
URLs signées à durée limitée pour le téléchargement des CV.
Limitation du débit (rate limiting) sur les endpoints d'authentification.
Suppression ou anonymisation des données d'un candidat sur demande (RGPD).
Dépendances scannées (Dependabot ou équivalent).
